Logboek probleem · hypothese · wijziging · resultaat · regel · nieuwste bovenaan

7 sep 2026Platform Compliance
probleem
Badr wilde live. De audit van 6 sep zei PASS voor de backend, maar de statische host zendiq.nl stuurde geen enkele security-header terwijl /dashboard en /admin daar staan; op de server stonden drie vergeten bestanden (_preview.html, _mobile-test.html en test-api.html, een debugpagina die met één klik een login-code aanvroeg voor een vast nummer); de privacyverklaring noemde geen verwerkers en geen doorgifte naar de VS; DMARC stond op p=none zonder rapportage; Dependabot-alerts stonden uit; PR #11 hing sinds mei; vercel.json was een restant; npm audit had qs op moderate.
hypothese
Headers via .htaccess in een IfModule-wrapper zijn veilig te zetten als de CSP uit een inventaris van alle pagina's komt en per pagina op nul overtredingen getest wordt; de rest is hygiëne die in één PR past; DMARC kan in twee fasen zonder mail te raken.
wijziging
Onderzoek van GitHub (privé, één beheerder, geen secrets in de volledige history, workflow-permissies read-only, anon-probe 37 tabellen 401) en van de site (headers, blootgestelde paden, DNS, TLS, webhook zonder handtekening 403). PR #41 (5 commits, rebase-merge): headers in public/.htaccess (HSTS, CSP, X-Frame-Options, nosniff, Referrer-Policy, Permissions-Policy), deploy.js slaat _-bestanden over en ruimt de drie stale bestanden op de server op (tests/deploy-upload-filter.test.js), privacy.html met verwerkers per land, doorgifte buiten de EER, grondslagen, alle AVG-rechten en klachtrecht, qs 6.16.0, vercel.json weg. Buiten git: drie bestanden per SFTP verwijderd, Dependabot-alerts aan (204), PR #11 gesloten, DMARC fase 1 via het TransIP-paneel.
